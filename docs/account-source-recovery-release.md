# 账户订阅恢复与 0.4.1 候选

2026-10-05（美西）；代码修复为 B 档，正式签名、发布与官网更新继续按已授权的 A 档发布流程验收。

## 问题与修复

删除最后一份活动配置会将来源保存为 `None`。登录和一键连接不会擅自撤销这一选择。如果本机也没有已缓存的账户配置或已确认交付，列表不会出现账户卡片；导入菜单原先又始终隐藏账户来源入口，因此这个状态下缺少重新选用账户订阅的入口。已有账户卡片仍可正常激活。

仅在已登录且来源为 `None` 时显示已有的“使用账户订阅”操作，复用 `ManualImportController.useAccount` 及既有来源提交门禁。选择后再由用户的一键连接发起账户交付和导入。普通导航、登录、删除、取消或打开菜单不自动切换来源；已有活动本地或远程配置时不显示这个入口。扫码、文件和链接三种导入方式保留。

未改变认证、后端、存储格式、来源授权或 VPN 内核。忙碌状态和取消操作继续阻挡来源切换。

## 验证与发布边界

- OPPO 正式 0.4.0 的短时网络校验失败曾显示登录页；通过普通导航重验后恢复已登录，无需再次输入凭据。第二次进程重启直接恢复已登录，不能把第一次联网失败解释为会话存储丢失。
- 独立 debug 测试包使用内存存储、合成 Portal/订阅传输和记录型连接回调，不读写正式包或原 candidate 的用户数据。
- 基线 4 项 UI 测试中，2 项因缺少账户恢复入口准确失败，另 2 项通过。修复后同组 4 项在 OPPO 全部通过，含账户选择后的一键交付、确认、下载及连接回调。控制器定向 22 项通过，含新增 3 项边界测试。
- Windows 完整 JVM 运行共 1127 项，其中 8 项失败；已直接观察到宿主文件系统拒绝临时文件的 POSIX 初始权限，相关完整测试不能记为通过。生产文件权限策略保持不变，仍须由本次提交的 Linux CI 完整运行确认。
- 上述 UI 使用 versionCode 7 的独立 debug 合成包验证修复行为；0.4.1 的完整 CI、正式签名 APK、真实账户订阅与 VPN、匿名公开下载均需按各自实际结果验收。本文准备记录不代表这些后续步骤已经通过。

新候选采用 `com.gccwebos.android` / `0.4.1` / versionCode `8`，复用已建立的正式签名，对现有正式 versionCode 7 进行覆盖升级。保留旧 0.4.0 产物及草稿，不覆盖历史验收材料。正式 APK 与完整对应源码经核验后，才开放官网稳定清单。

配置库 v3 只能用兼容的更高版本前向修复，不能靠降级或清除用户数据回滚。历史 B2 P7 超时未解决，P8/P9 未执行；本次 UI 修复不改变该结论。
