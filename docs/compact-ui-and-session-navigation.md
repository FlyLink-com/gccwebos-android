# 紧凑界面与会话返回导航

## 范围和风险

本轮按 B 档处理：在同一 PR 内调整 Compose 界面、页面导航与局部选择行为，并补充边界测试。本文记录实现及已完成的本地合成测试、构建和覆盖安装；真实账户与节点流量的验收边界见文末。

本轮承接 [ui-preview-v2-alignment.md](ui-preview-v2-alignment.md) 的四页原生布局，根据后续需求继续缩小卡片、合并分组和调整交互。历史文档中的验证身份和结果不自动适用于本轮代码。

## 固定视觉资源与真实数据

机器人、图标和背景继续使用本地固定资源。账户身份、有效期、流量、余额、价格、可购目录和节点列表仍分别读取原有控制器与验证后的数据；HTML 示例数据不作为运行时默认值。

欢迎标题的展示名称按当前已告知用户的默认映射处理，仅匹配以下公开 `Resource.Available.plan` 标识：

| 精确资源计划 ID | 展示名称 |
| --- | --- |
| `monthly_30d_50gb` | Go 订阅 |
| `monthly_30d_100gb` | Plus 订阅 |
| `yearly_365d_200gb` | 年 Plus 订阅 |

映射定义在 `design/SubscriptionTitle.kt`。它只改变名称展示，不修改商品、价格、时长、流量、购买权限或连接权限。大小写变化、后缀变化和未知 ID 不套用近似名称；其余已验证资源回退到原真实时长文案，未验证资源显示中性账户标题。到期信息继续独立显示，名称不代表权益仍有效。

## 套餐默认重置与订单恢复

`MainActivity.kt` 为每次套餐导航请求递增 `plansVisit`，传入 `CommercePanel.defaultSelectionRequest`。页面不通过重建控制器来实现同页重置。只有当前会话可操作、商务请求空闲且没有 `pendingPurchase` 时，才清除页面选择、临时报价和旧 `purchaseReturnRef`，再由 `initialMonthlyCatalogOffer` 匹配当前目录；此过程不发起报价或订单请求。

展示选择保存完整 `Offer` 快照并绑定账户 generation。同一商品引用的版本、价格或权益变化不能沿用旧选择；购买按钮及确认按钮仍检查当前目录、完整快照、会话、忙碌状态、报价有效期与未决订单。

被删除的返回快捷入口只关联内存中的商品引用。持久化恢复仍由 `CommerceRecovery` 和 `CommerceRepository` 保存原输入引用、原订单结果及幂等键，页面默认重置不调用恢复记录清除。未决订单继续显示“查询／恢复原订单”，只有原有明确核对流程能完成或清理记录。

套餐及钱包的展示缓存按控制器和当前 `commerceSessionIdentity` 隔离；没有该 identity 的离线调用按 `authSessionGeneration` 隔离。读取显示还检查 `currentSession()`。当前目录、余额与档位的加载状态仍控制实际动作，展示缓存不回写权威状态。换账户、换会话绑定或失去当前会话资格不能借缓存继续下单或付款。

## 保存会话与返回键

本轮修复两个导航入口：AppShell 的系统返回处理，以及“我的”子页的系统返回处理。两者统一调用 `shouldCancelLoginOnBack`。已认证账户的普通安全读取、启动恢复、前台复核或 `restorationPending` 期间，返回只执行页面导航，不再因为 `account.busy` 就调用 `cancelAuthentication()` 并清除保存会话。

真正未认证的新登录或 TOTP 操作仍可通过原取消路径结束。此改动属于导航条件修复，不修改认证模型、持久化格式、加密存储或原生会话期限。`SavedSession.MAX_NATIVE_SESSION_MILLIS` 仍为 30 分钟；服务端到期、已用墙钟/单调时间和恢复校验仍限制实际剩余期限。期限到期后需要重新登录，不应归因于本轮已修复的返回路径。

## 随机节点的两阶段准备

`OneClickConfigGateway` 优先沿用当前有效手动选择。没有选择时，先由 `LocalSubscriptionManager.prepare(Choose)` 进行新鲜读取，确认本次可选节点及选择对象仍属于当前注册表，再从合法候选中随机取一个；随后调用 `prepare(Selected(...))` 进行第二次新鲜校验并准备材料。

随机选择通过 `NodeSelectionAttempt` 记录同锁快照与 epoch，并由 `selectNodeIfUnchanged` 原子核对注册表、epoch 和仍未选择的状态；首次读取和第二次读取均使用 `prepareAtEpoch`，首读返回后必须仍处于该次读取生成的 epoch，失效即取消。自动选择不能覆盖并发到达的手动选择，也不能在取消后重新取得读取资格。

随机选择仅是当前明确连接请求中的本地意图，不在打开页面、登录恢复或普通列表读取时执行。注册表改变、会话失效、节点为空、不兼容材料或第二次读取失败均继续由原有验证路径拒绝。连接 owner、服务生命周期和 native 内核边界不因页面缩小或自动选择而改变。
