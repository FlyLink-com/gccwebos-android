# 开发顺序与验收

当前产物为规划文档；以下工程、构建、连接和接入项目均待实现及验收。

## M0 独立仓库与可构建 App 基线

- 客户端使用独立私有仓库 `gccwebos-com/gccwebos-android`，采用单一 `app` 模块。主分支保护、PR 评审规则、秘密扫描与构建 CI 在工程阶段逐项配置并回读确认。
- 创建 Kotlin／Compose 工程、Gradle wrapper 和 debug 构建；锁定工具版本，记录开发 applicationId、最低 Android 版本和支持设备。正式发布身份与签名保管方案在签名交付前冻结。
- 实现连接、线路、套餐、我的四个入口及本地状态模型。示例数据须明确标记，未接入能力保持未接入状态。
- 本阶段不依赖后台 API 地址、测试账户、节点配置或发行私钥；首次 debug 构建使用开发签名。
- 验收：本地 `./gradlew :app:assembleDebug`（Windows 使用 `.\gradlew.bat :app:assembleDebug`）成功，App 能启动和切换四个入口；CI 以实际运行结果单独记录。构建成功不计为真实 VPN 或后台联调通过。

## M1 真实 VPN 连接（最高优先级）

- `VpnService` 授权、前台服务、TUN 生命周期和内核适配。隔离实验使用获准的测试配置，账户授权配置获取在后台接入阶段实现。
- 自动／手动线路、实际流量探测、断开、重连、网络切换和进程恢复。
- 真机验收：首次系统授权；连接后 DNS／网页／获准测试目标可用；断开后路由恢复；切换 Wi-Fi／蜂窝后可恢复；撤销授权后准确提示。权益接入后另行验收过期权益阻断新连接。
- 无可用内核或协议不兼容时停止发布，不用假连接代替。

## 接入准备（按功能需要触发）

- 对准备接入的能力读取后台当前 commit、原生 Issue／PR 和真实 API；此前引用的 Issue #438 需重新核对。
- 确认测试 API 地址、隔离测试账户、获准节点配置与接口样例。真实凭据和节点材料不提交到仓库。
- 逐项确认认证、权益、线路配置、订单、支付或推荐合同，再替换对应客户端数据实现；只补齐本阶段需要的后台能力。
- 该阶段不作为 M0 构建和页面开发的前置条件。涉及生产、认证模型或 schema 的后台变更在后台仓库按其风险门禁执行。

## M2 账户与购买

- 邮箱验证、注册、登录、会话恢复、退出；服务端商品与报价；月卡／年卡购买和续费。
- 资源展示、购买／充值订单、钱包、开通中与失败状态。
- 验收：重复点击仅一笔订单；超时可恢复；支付回跳后重查；商品下架或价格变动重新确认；未知流量不显示零。

## M3 推荐与签名测试包

- 分享链接、邀请码、归因确认、奖励状态、支持入口、维护公告。
- 签名 APK、版本号、更新提示、隐私说明、崩溃与脱敏连接诊断。
- 验收：已安装／新安装的推荐路径；错误码到文案；至少两类 Android 设备与多个系统版本真机回归；安全审查和内核许可证核对。

## M4 Google Play 渠道（独立发布门槛）

- 评估具体国家／地区的付款规则；实现符合对应渠道要求的购买流程与服务端核验。
- 完成 `VpnService` 声明、数据安全、隐私披露、商店素材、内部测试与审核问题修正。

## 首轮任务拆分

1. Android 工程、构建与 CI。
2. Compose 四入口、本地状态模型与明确标记的展示数据。
3. 内核候选、协议兼容与许可证验证。
4. VPN 服务与连接状态机真机实验。
5. 按功能需要审计后台合同，接入认证、权益、授权线路和连接配置。
6. 订单幂等和支付状态恢复。
7. 推荐归因及签名 APK 交付。

后端缺少的能力在后续接入时于 `proxy-gateway-minimal` 实现，Android 仓库只放客户端和脱敏契约测试样例。每个任务分别标记责任仓库、依赖项和验收证据。
