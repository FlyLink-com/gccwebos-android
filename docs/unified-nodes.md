# 统一节点：账户订阅与导入配置都只是“节点来源”

状态：设计说明 + 第一步最小风险实现（本 PR，草稿）。基线 `main 3de35d3`（0.4.2）。

## 目标（Ethan 的决定）
- 账户订阅和导入配置只是节点的**来源**；节点页是**一个**合并的节点列表，每个节点标明来源，并可按来源筛选。
- 选节点就是选出口，不再有“先切换当前使用哪份配置”这一步。
- 账户订阅节点**只读**（由服务端下发，刷新会重新出现）；导入配置的节点可在本地**重命名/删除**，改动在刷新后保留。
- 选中状态持久（PR #50 的单向 key 哈希）。
- 修复：先导入配置、之后登录，账户节点永远加载不出来。

## 现状（为什么不能一步到位）
- `LocalSubscriptionAuthority` 只保存**一个**“当前来源”的节点注册表（`choices` / `choiceKeys` / `selected`），选择器是 `Account | None | Entry(id)`。
- 连接准备（`FreshConnectionConfig`、`OneClickConfigGateway`、`ConnectionCoordinator`）按这个唯一来源下载/校验并生成配置；账户订阅需要账户授权，导入配置没有；两者的到期、撤销、续期规则不同。
- 来源切换必须通过 connection owner 的 idle fence（隧道活着时不能换），并撤销旧的 selection/admission。
- 账户订阅行只有在已缓存 profile 或存在未待确认的 delivery 时才出现在库里。已导入配置时选择器停在 `Entry`，登录后不会自动下载账户订阅，所以账户行不出现；导入页里「使用账户订阅」又只在 `sourceKind == None` 时显示 → 用户没有任何入口回到账户订阅（Bug）。

真正的“一个合并注册表、点节点即用，不经过来源切换”需要：多来源同时有效的节点注册表、按节点所属来源做准入（账户授权/到期/撤销）、连接时按所选节点所属来源生成配置、以及隧道活着时的多来源只读行为。这动到准入与连接准备的安全边界，不适合一个 PR 里完成。

## 本 PR 做了什么（不改准入与存储格式）
1. **账户行始终可选（修 Bug）**：登录状态下，库快照总是包含“账户订阅”行；没有缓存时显示为「待加载」，“选择配置”走原有的 `activateConfiguration(account)`（栅栏 + `refresh()` 下载并验证）。已导入的配置、选中节点、库内容都不动。实现：`configurationLibrarySnapshot(accountSignedIn)`、`ConfigurationLibraryController(accountSignedIn=…)`。
2. **「使用账户订阅」不再要求 `sourceKind == None`**：任何已登录且当前来源不是账户的情况都可用（`canUseAccountSource`）。
3. **点节点即选出口（一步）**：每个来源分组展开后，节点行可直接点击。点击 = 用原有的、带栅栏的激活路径把该来源设为当前来源，然后在新注册表里选中同一个节点：先按“同位置且名称/协议一致”，否则按“名称+协议唯一”匹配（`matchNodeTarget`）。**匹配不到、不唯一或下载后节点变了，不会选别的节点**，提示「节点已变化，请重新选择节点」。选中后走原有的 `selectNode` → 持久化（`entry:<id>` / `account` 作用域，单向 key）。
4. **来源标签**：每个来源分组的副标题为「N 条 · 来源 · 状态」，来源是 账户订阅 / 订阅配置 / 本地文件 / 第三方订阅。
5. 只读/可编辑沿用现有规则：账户行菜单只有「查看」；导入配置可重命名、替换、删除（整份配置级别）。

## 没做（明确不在本 PR）
- **一个真正合并的注册表**：所有来源的节点同时可被选中、无需切换来源；仍然是“点节点 → 切换来源并选中”。隧道已连接时不能换来源（沿用“请先断开连接”）。
- **按来源筛选**：没有筛选条。
- **单个节点的重命名/删除**：目前只有整份配置的重命名/删除。建议第二步：旁路加密 sidecar，按（来源作用域，节点单向 key）存显示名覆盖与“已删除”标记；注册表构建与配置生成时应用（隐藏的节点不进入生成的配置），刷新后保留；账户来源不允许写入。需要存储格式与迁移的单独评审。
- 账户订阅登录后**自动**加载（本 PR 需要用户点一次）。自动加载会在导航里触发下载，与“导航读取不下载”的现有约束冲突，需另议。
- 活动来源分组标题的来源标签（标题的 UI 契约 `nodes-group-title` 被现有 UI 测试固定）。

## 风险
- 激活来源仍是远程下载 + 栅栏；账户来源首次点击会联网下载订阅。失败时保持原来源，显示固定文案。
- 节点匹配只依据“位置 + 名称 + 协议”；服务商若重名且重排，会提示重新选择，而不是猜测。
- 账户占位行在登录期间一直存在；它在未登录时不会出现（没有账户就不虚构账户行）。
- 未在真机上验证；节点行点击区域的可用性（带宽/无障碍）需要在 OPPO 上看一眼。
