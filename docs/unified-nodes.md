# 统一节点：账户订阅与导入配置都只是“节点来源”

状态：设计说明 + 第一步最小风险实现（本 PR，草稿）。基线 `main 3de35d3`（0.4.2）。

## 目标（Ethan 的决定）
- 账户订阅和导入配置只是节点的**来源**；节点页是**一个**合并的节点列表，每个节点标明来源，并可按来源筛选。
- 选节点就是选出口，不再有“先切换当前使用哪份配置”这一步。
- 账户订阅节点**只读**（由服务端下发，刷新会重新出现）；导入配置的节点可在本地**重命名/删除**，改动在刷新后保留。
- 选中状态持久（PR #50 的单向 key 哈希）。
- 修复：先导入配置、之后登录，账户节点永远加载不出来。

## 现状（为什么不能一步到位）
- `LocalSubscriptionAuthority` 只保存**一个**“当前来源”的节点注册表（`choices` / `choiceKeys` / `selected`），选择器是 `Account | None | Entry(id)`。
- 连接准备（`FreshConnectionConfig`、`OneClickConfigGateway`、`ConnectionCoordinator`）按这个唯一来源下载/校验并生成配置；账户订阅需要账户授权，导入配置没有；两者的到期、撤销、续期规则不同。
- 来源切换必须通过 connection owner 的 idle fence（隧道活着时不能换），并撤销旧的 selection/admission。
- 账户订阅行只有在已缓存 profile 或存在未待确认的 delivery 时才出现在库里。已导入配置时选择器停在 `Entry`，登录后不会自动下载账户订阅，所以账户行不出现；导入页里「使用账户订阅」又只在 `sourceKind == None` 时显示 → 用户没有任何入口回到账户订阅（Bug）。

真正的“一个合并注册表、点节点即用，不经过来源切换”需要：多来源同时有效的节点注册表、按节点所属来源做准入（账户授权/到期/撤销）、连接时按所选节点所属来源生成配置、以及隧道活着时的多来源只读行为。这动到准入与连接准备的安全边界，不适合一个 PR 里完成。

## 本 PR 做了什么（不改准入与存储格式）
1. **一个合并的节点列表**：节点页只有一张“节点列表”卡片，所有来源（账户订阅 / 订阅配置 / 本地文件 / 第三方订阅）的节点都在里面，**每一行标明来源**（如「配置 1 · 本地文件」「官方 · 只读」）。当前来源的节点保留延迟测试/选中；其他来源的节点同样是行，不再需要展开分组。来源多于一个时有**来源筛选条**。下方「来源」卡片列出每个来源，整份配置的重命名/替换/删除在那里。
2. **点节点即选出口（一步）**：点其他来源的节点 = 用原有的、带栅栏的激活路径把该来源设为当前来源，再选中同一个节点（`matchNodeTarget`：同位置且名称/协议一致，否则名称+协议唯一）。匹配不到或不唯一不会选别的节点，提示「节点已变化，请重新选择节点」。选中状态沿用 #50 的单向 key 持久化（`entry:<id>` / `account`）。
3. **已连接**：隧道连接中/连接/断开中，其他来源的节点置灰并提示「已连接时只能选用当前来源的节点；要用其他来源的节点，请先断开连接」（最低风险：不在连接中换来源）。当前来源内的选择行为不变；连接中不能删除当前来源的节点。
4. **单个节点重命名/删除（仅导入配置）**：每行的「⋯」→ 重命名 / 删除（删除有确认）。账户订阅节点只读，没有菜单，写入入口也拒绝账户作用域。
   - 存储：新的加密 sidecar `NodeOverrideStore`（`node-override.bin`，AES-GCM，no-backup），按（作用域，节点单向 key）保存本地别名与“已删除”标记；不改订阅文件、不改生成的连接配置、不碰准入。key 与 #50 相同（名称+规范化节点的摘要），所以订阅刷新后节点身份没变就保留别名/删除；节点身份变了（服务商改了名或参数）则视为新节点。同一份配置里 key 重复的节点无法单独编辑。
   - **已删除节点 / 恢复**：本地删除的节点不在主列表里，而是放在列表底部单独的「已删除节点」卡片（默认折叠，没有删除的节点时不显示，随来源筛选）。每行只有「⋯ → 恢复」：不能选、不延迟测试、不能重命名/再删。恢复 = 清掉删除标记，节点回到主列表，保留它之前的本地别名；恢复不会把它重新设为选中。账户订阅节点不能删除，所以不会出现在这里。删除/恢复都存在同一个 `NodeOverrideStore` 里，刷新和重启后保持（删除时保留别名，恢复时别名随之回来）。
   - 删除 = 本地隐藏：在注册表里把该节点标成与“服务商通知”同级的不可选/不延迟测试/不自动挑选项，列表不显示；注册表的下标与生成配置保持一致（没有过滤节点）。删除的是当前选中的节点 → 选择清空并忘掉持久化的选择，需要重新选。删除整份配置会同时清掉它的节点改动；清除本地数据会清空全部。
   - 别名只是显示名；地区图标仍按显示名推断。
5. **账户节点自动加载**：已登录且账户订阅尚未加载时，进入节点页自动加载一次（每次登录/页面一次）；但**只在不会顶掉用户已选节点、没有隧道、没有忙碌操作时**。如果其他来源里已经选了节点，账户行显示「点一下加载账户订阅的节点」，由用户点。
6. 先导入配置、再登录时账户行始终出现（`configurationLibrarySnapshot(accountSignedIn)`），「使用账户订阅」不再要求 `sourceKind == None`。

## 没做（明确不在本 PR）
- **一个真正同时有效的多来源注册表**：仍然只有一个当前来源的注册表；点其他来源的节点会先切换来源。隧道连接中不能换来源。要做需要按节点所属来源做准入与生成配置，动安全边界，需单独评审。
- 账户来源已有选中节点时的自动加载（见上，有意不做，避免顶掉用户的选择）。

## 风险
- 激活来源仍是远程下载 + 栅栏；账户来源首次加载会联网。失败时保持原来源，显示固定文案。
- 节点匹配只依据“位置 + 名称 + 协议”；服务商重名且重排时提示重新选择，而不是猜测。
- 别名后的名字与原名不同，延迟测试/排序按显示名；地区图标按显示名推断。
